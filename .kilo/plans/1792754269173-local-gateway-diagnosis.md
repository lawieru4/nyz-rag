## 执行步骤
1. 无需修改源码、迁移数据库或重启整套服务。将该供应商 API 地址改为 `http://host.docker.internal:8317/v1`，保持现有 Key，在保存前测试连接。
2. 若成功返回模型列表，保存供应商，在业务模型中选择其实际支持的 Chat 模型，再验证一次问答。列表可用不代表推理一定可用。
3. 若仍为网络异常，在具备执行权限后，从 API 容器探测 `http://host.docker.internal:8317/v1/models`，仅输出状态码及脱敏网络错误，不输出 Key、响应正文或全量环境变量。不带 Key 返回 401/403 也能证明网络已通。
4. 若容器仍无法连接，检查宿主机 CLIProxy 的 8317 监听、Docker 到宿主机的可达性及 Windows 防火墙。仅在确认监听范围阻止访问时调整网关绑定，并限制访问范围、保留鉴权，不直接向公网开放。
5. 若返回 401/403，核对 CLIProxy 的客户端访问 Key；若返回 404，核对 `/v1/models` 路径；若返回无效模型列表，核对 OpenAI 兼容的 `data[].id` 格式。
