# Repository Instructions

- This is a pnpm workspace (`apps/*`, `packages/*`); shared frontend/API contracts live in `packages/types` and are imported as `@nyz-rag/types`.
- `apps/web` and `apps/admin` are separate Vue 3/Vite applications; `apps/api` is the Fastify entrypoint and `apps/worker` consumes the BullMQ `document-processing` queue.
- All modules must prioritize reusing existing components. Before adding or changing UI, check `packages/ui` (`@nyz-rag/ui/components/*`) and existing application components; use them instead of duplicating implementations or using raw HTML controls when an equivalent component exists. Only add a new component when existing components cannot meet the requirement; place reusable UI components in `packages/ui` and follow the established component conventions.
- Root commands: `pnpm dev` starts API, web, and worker (not admin); `pnpm build` builds all workspace packages; `pnpm typecheck` typechecks all packages.
- Focused commands: `pnpm --filter @nyz-rag/<api|web|admin|worker|types> dev|build|typecheck`. API and worker use `tsx watch`; Vue apps use Vite and `vue-tsc`.
- Local development reuses shared PostgreSQL 18/pgvector at `localhost:5432` and Redis 8 at `localhost:6379`. Use the dedicated `nyzrag` database/role and set `DOCUMENT_QUEUE_NAME=nyz-rag-document-processing` in both API and worker. Do not change booth-ai services. Optional isolated services require `docker compose --profile standalone up -d postgres redis` and URLs using ports 55433/56380.
- `docker compose up -d --build --wait` builds the root multi-stage Dockerfile and starts only api/worker/web/admin in the `nyz-rag` project. Backend startup rewrites loopback dependency hosts to `host.docker.internal`. Do not run host and container workers on the same queue at the same time. Frontend Nginx proxies same-origin `/api/` to api:3000. Published ports bind only to 127.0.0.1.
- `.env` is gitignored; `.env.example` documents the local environment. API, worker and both Vite apps load the root `.env`. Defaults in the template are API 3001, web 5175 and admin 5176; Vite reads `VITE_API_URL` for the client API endpoint.
- API and worker share `packages/processing` storage: all metadata and vectors are in PostgreSQL. Tables are defined with Drizzle ORM in `packages/processing/src/schema.ts`; `pnpm db:generate` creates migrations in `packages/processing/migrations`, which run on API/worker startup (`pnpm db:migrate` runs them manually). An administrator must provision the vector extension for the non-superuser application role.
- Data sources are nyzdata article API sources only (web site crawling was removed; the database enforces `kind = '文章 API'` and requires `raw_json`/`external_id`). They use the article list endpoint as the source URL; the token is a single admin-configured secret (`PUT /api/admin/settings/article-token`, write-only) read by the worker on each sync, and must never be written to URLs, logs, code or commits. Admin-configured secrets (article token, model API keys) are AES-256-GCM encrypted with `NYZ_SECRET_KEY` (required by API and worker, at least 32 characters); APIs only report whether a secret is set. Parsing (`packages/processing/src/article/parse.ts`, ported from `scripts/nyz-articles/parse.mjs`) and structured chunking (`chunking.ts`) are pure functions covered by `test/article.test.ts`; raw article JSON is kept in `documents.raw_json` so reprocessing re-parses without refetching.
- The API is split into Fastify plugins per domain (`chat`, `search`, `documents`, `data-sources`, `crawl-tasks`, `knowledge-bases`, `model-providers` (providers and model settings), `common`) assembled by `apps/api/src/app.ts`. Request/response JSON Schemas live in `apps/api/src/schemas.ts`, keyed by `"METHOD /path"` and attached by an `onRoute` hook; every route must have an entry (enforced by `apps/api/test/app.test.ts`), and response schemas drop undeclared fields. All errors are `{ error: string }`. Queue access goes through `apps/api/src/queue.ts`. Frontends use the shared fetch/SSE client `packages/api-client`.
- Chat routes live in `apps/api/src/chat.ts`: `/api/chat` (single answer) and chat sessions with SSE streaming (`POST /api/chat/sessions/:id/stream`, events `source`/`token`/`done`/`error`; regenerating supersedes the latest message; client disconnects abort the model call and nothing is saved). Both run hybrid retrieval (`rag.ts`: keyword search over app-generated NFKC/bigram terms stored as `tsvector` plus pgvector chunk search and summary-level recall over `documents.summary_embedding` (title + summary vector; recalls articles, then their best chunk), RRF fusion, optional rerank) and streams the default chat provider's model (`models.ts`; chat, embedding and rerank each have their own default provider), falling back to an extractive answer. Retrieved chunks, scores and timings are logged in `message_chunks` / `chat_messages`. Run `pnpm db:reindex-search` after changing `search-terms.ts`; the worker backfills missing terms on startup. Covered by `test/retrieval.test.ts`.
- Use `pnpm typecheck`, `pnpm build`, `pnpm --filter @nyz-rag/processing test`, `pnpm --filter @nyz-rag/api test` and `pnpm --filter @nyz-rag/api-client test` for verification. Set `NYZ_INTEGRATION_TEST=1` with `DATABASE_URL` and `REDIS_URL` to enable the API/queue/worker integration test; it uses a temporary PostgreSQL schema and unique queue.
