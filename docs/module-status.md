# 模块清单与开发进度

本文记录架构模块范围、已实现能力和推荐开发顺序。状态按仓库现有代码评估，不代表生产就绪。

## 模块数量

- 架构方案定义 9 个逻辑业务模块，见 `rag-system-architecture.md` 第二章。
- 管理后台定义 5 个运营模块，见 `rag-system-architecture.md` 第四章。它们是逻辑业务模块的管理端视图，不应与 9 个模块相加当作互不重叠的总数。
- 服务端目录方案另列 17 个 API 子域（含 common），属于实现拆分建议，也不等于 17 个产品模块。

## 推荐实施顺序

按管理端当前开发序列继续：

1. 真实内容采集：来源启停、授权/robots 检查、任务状态与错误处理。
2. 内容清洗与文档切片：定义可追溯的数据模型和重处理流程。
3. Embedding 与向量持久化：接入模型 Provider 和 pgvector。
4. 混合检索、Rerank 与真实 RAG：结合知识库参数生成可引用答案。
5. 账号权限、会话历史、审计及运营指标。
