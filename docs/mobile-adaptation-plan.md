# 客户端与管理端移动适配计划书

适用项目：nyz-rag

## 1. 目标与边界

### 1.1 建设目标

在保留现有视觉风格、桌面布局和业务行为的前提下，使客户端与管理端能够在手机、平板及桌面浏览器中完成主要操作，而不只是缩小显示。

- 客户端：能够完成登录、提问、流式阅读、停止生成、查看引用、阅读文章和切换会话。
- 管理端：能够完成导航、查询、查看详情，以及权限允许的新增、编辑、确认等现有管理操作。
- 共享组件：弹窗、抽屉、表单、表格和操作按钮具备明确的窄屏、短屏与触控行为。
- 桌面端：保留原有信息密度与效率，不因移动端改造损失列信息、权限控制或操作入口。

### 1.2 本期范围

覆盖客户端聊天页、文章页、账号弹窗，以及管理端登录入口和全部现有业务路由：数据源、文档管理、知识库、问答记录、用户管理、模型配置、管理员管理、角色管理、操作日志、个人资料。

本期不包含原生 App、PWA/离线能力、全站视觉重设计、新业务功能、API 协议调整或数据库变更。响应式实现优先使用现有 Vue 3、Tailwind CSS 与共享 UI，不预设引入新组件库。

### 1.3 支持基线

| 维度 | 本期目标 |
| --- | --- |
| 最小布局宽度 | 320 CSS px，关键内容和操作不被裁切 |
| 常用手机宽度 | 360、375、390、430 CSS px |
| 平板与桌面 | 768、1024、1280、1440 CSS px |
| 屏幕方向 | 竖屏、横屏；包含短视口和键盘弹出后的可视区域 |
| 浏览器 | 验收时最新稳定版及前一主要版本的 iOS Safari、Android Chrome；桌面 Chromium、Firefox、Safari 的可用测试环境 |
| 缩放与可访问性 | 不禁用用户缩放；检查 200% 缩放下的内容和操作可达性 |

微信等内嵌 WebView 作为补充观察项，不在未实测前宣称兼容。验收记录必须填写实际系统、浏览器及版本；未覆盖的环境明确列为验证缺口。

## 3. 统一适配规则

### 3.1 断点与布局

- 沿用 Tailwind 默认断点（`sm` 640、`md` 768、`lg` 1024、`xl` 1280px，主题未覆盖）。JavaScript 媒体查询须与之一致，如客户端引用第三栏的 `matchMedia("(min-width: 1280px)")` 对应 `xl`。
- 小于 640px：优先单列，表单控件占满可用宽度，操作区允许换行或纵向排列。
- 小于 768px：管理端采用抽屉导航，主内容取消常驻侧栏左边距；宽表优先展示移动端摘要列表。
- 768px 至 1023px：管理端保留紧凑导航，客户端继续使用会话抽屉；按容器空间调整筛选和表单列数。
- 不小于 1024px：保留桌面主布局；客户端引用第三栏继续遵循现有 1280px 条件，不强制统一所有业务断点。
- 在边界前后各验证 1px，例如 767/768px、1023/1024px、1279/1280px，避免导航重复、内容消失或遮罩残留。
- 对承担长内容的 Flex/Grid 子项按需补充 `min-w-0`、`min-h-0`，不使用全局 `overflow-x: hidden` 掩盖布局错误。

### 3.2 滚动、弹层与键盘

- 普通页面不得产生非预期横向滚动；代码、数据表格等允许在明确的局部容器内横向滚动。
- 弹窗按动态视口高度限制最大高度；长表单优先使用单一正文滚动区，避免多层滚动相互争抢。
- 弹窗标题、关闭入口和提交操作必须可达。短屏时允许滚动到操作区，不强制使用占据过多高度的固定头尾。
- 抽屉和弹窗打开时锁定背景滚动，关闭后恢复触发元素焦点；跨断点切换时不遗留遮罩或滚动锁。
- 安全区：当前未设置 `viewport-fit=cover`，浏览器自行避开不安全区域，`env(safe-area-inset-*)` 取值为 0。先决定是否启用 `viewport-fit=cover`；启用后才需要为输入区、底部操作栏、固定顶栏和横屏左右边距补充 `env(safe-area-inset-*)`，并同步验证四个方向。
- 视口高度统一用 `dvh`（或按需 `svh`），替换现有的 `100vh` 与 `min-h-screen`。
- 优先使用 CSS 和动态视口单位解决键盘问题；只有真实复现且 CSS 无法解决时才评估 `VisualViewport`，不预先增加全局监听与补偿逻辑。
- 移动端输入控件字号不小于 16px，避免 iOS Safari 聚焦时自动缩放。共享 `Input`、`Textarea` 默认 `text-base md:text-sm` 已满足，调用方不得在小屏覆盖为更小字号（现有客户端筛选输入需修正）。

### 3.3 触控与可访问性

- 主要触控目标按至少 44×44 CSS px 设计，可通过扩大点击区域保留原有图标尺寸。
- 图标按钮提供可访问名称，不依赖 hover 提示才能理解或执行操作。
- 菜单、弹窗和抽屉保留键盘操作、焦点约束及关闭行为；优先复用现有 Reka UI 机制。
- 长标题允许截断或换行，但完整内容必须能在详情中获取；关键状态、错误提示和操作名称不能只靠截断展示。
- 删除、权限修改和同步等操作保留已有确认、禁用和防重复提交逻辑，不因移动布局降低保护措施。

## 5. 管理端实施内容

### 5.1 导航与页面骨架

手机端将常驻图标侧栏改为顶部菜单按钮加抽屉导航，抽屉内保留模块名称、当前选中状态和账号入口；平板及桌面继续使用原有侧栏体系。

- 复用现有菜单数据和 `routeVisible` 权限判断，不为移动端维护另一套权限列表。
- 抽屉菜单内容可纵向滚动；点击路由后关闭抽屉，再次选择当前模块保留现有刷新语义。
- 路由切换、退出登录、横竖屏切换和进入桌面断点时，正确处理抽屉状态与焦点。
- 页面标题、筛选区、批量操作区、分页统一允许窄屏重排；不在手机端丢失现有操作能力。

主要涉及：`AdminLayout.vue`、`AdminSidebar.vue`、`AdminHeader.vue`、`PageHeading.vue` 及业务视图。

### 5.3 表格实现约束

- 桌面继续使用原表格；手机摘要列表和桌面表格共享数据、筛选、分页、选择状态及操作处理函数，不复制请求和业务状态。
- 优先在业务视图内完成轻量展示分支；只有出现稳定重复模式后再抽取组件，不预先创建通用移动表格框架。
- 对确需横向比对的宽表，保留局部滚动和可发现的滚动提示，不把整页横滚作为默认解决方案。
- 隐藏次要列必须同时提供完整信息的查看路径；存在批量操作的页面必须验证跨布局切换后的选择状态。
- 确保隐藏分支不能被键盘聚焦，不产生重复表单 ID、重复弹层或重复数据加载。

## 8. 验证方案

### 8.1 证据与责任

角色在实施时落实到具体人员；同一人可兼任，但每项验收结论必须有明确责任人。

| 验证主张 | 责任角色 | 最小证据 | 局限与升级条件 |
| --- | --- | --- | --- |
| 页面不会非预期横向溢出 | 对应端实现负责人 | 手机、平板、桌面截图；页面滚动宽度与视口宽度检查；宽内容样例 | 截图不能证明交互正确，出现溢出需定位具体容器 |
| 键盘、安全区不阻塞输入 | 客户端实现负责人，验收负责人复核 | iOS Safari 和 Android Chrome 真机操作记录 | 桌面设备模拟不能替代软键盘验证；无设备时记录未验证，不判通过 |
| 管理操作和权限不回归 | 管理端实现负责人 | 超级管理员、受限管理员分别完成允许的路径；无权限入口检查 | 不因 UI 隐藏就推断后端鉴权通过；权限逻辑若变化需扩大 API 测试 |
| 弹层焦点与滚动正确 | 共享 UI 负责人 | 打开、输入、滚动、关闭、焦点恢复及跨断点操作记录 | 共享默认样式变化时，两端所有弹层类型都要重测 |
| 桌面行为和工程构建不回归 | 集成验收负责人 | 桌面前后截图、类型检查、构建和相关现有测试结果 | 工程检查不能代替视觉和触控验收 |

优先使用现有开发环境和浏览器能力。当前检查未发现 Playwright 配置，不假定已有浏览器端到端测试设施；若需要新增依赖或长期截图基线，单独确认范围后实施。手工矩阵为最低可执行路径，浏览器自动化可增强重复性，但不能代替真机键盘测试。

### 8.2 测试数据与场景

- 内容：空数据、单条记录、多页记录、超长中英文标题、连续字符串、长 URL、宽 Markdown 表格、长代码。
- 聊天：未登录、已登录、空会话、多轮会话、流式输出中、停止生成、重新生成、错误提示、长引用列表。
- 表单：空字段、服务端校验错误、长错误提示、加载/禁用状态、密码输入和长权限清单。
- 导航：直接进入受保护路由、权限不足、路由切换、当前模块重选、退出登录、抽屉打开时切换断点。
- 设备：竖屏、横屏、短视口、键盘打开/关闭、浏览器地址栏收起/展开、200% 缩放。
- 数据安全：使用测试账号、合成内容和可恢复记录；不为测试触发生产同步或删除真实数据，截图不得包含 token、API key、密码和真实敏感内容。

### 8.3 必测旅程

| 编号 | 操作路径 | 结果要求 |
| --- | --- | --- |
| T1 | 手机登录 → 输入问题 → 展开筛选 → 发送 → 阅读流式回答 → 停止/重新生成 | 控件可达，无重复提交；输入和内容不被键盘或固定区域挡住 |
| T2 | 打开会话列表 → 切换会话 → 查看引用 → 打开文章 → 返回 | 抽屉、引用和会话状态符合现有逻辑，阅读区域正常 |
| T3 | 管理端登录 → 打开导航 → 切换全部授权模块 → 查询和分页 | 无丢失入口，筛选和分页可用，页面无非预期横滚 |
| T4 | 角色编辑/模型设置 → 输入长内容 → 制造校验错误 → 修正 → 保存或取消 | 字段、错误和操作区可达，长表单不超出可操作范围 |
| T5 | 文档/问答详情 → 长内容滚动 → 打开操作弹窗 → 关闭各层 | 焦点和滚动锁恢复正确，没有遮罩残留 |
| T6 | 受限管理员访问授权与未授权页面；桌面重复主要旅程 | 权限不扩张，桌面列信息和操作能力保持不变 |

在 320、390、768、1440px 上覆盖全部页面基础检查；关键旅程补测 360、375、430、1024、1280px 及断点边界。真机至少完成 T1、T2、T4 和 T5，并检查手机横屏，不要求每个页面与每个设备做无差别全排列。

### 8.4 工程验证与环境

前端聚焦检查：

```sh
pnpm --filter @nyz-rag/web typecheck
pnpm --filter @nyz-rag/admin typecheck
pnpm --filter @nyz-rag/web test
pnpm --filter @nyz-rag/admin test
```

集成收口检查（按仓库约定，依次执行构建、类型检查与全部包测试）：

```sh
pnpm verify
```

现有测试用于行为回归，不能证明移动视觉通过。本次计划阶段不执行上述构建或测试；实施后的结果须另行记录。只有涉及 API/队列/worker 行为变化时才扩大到真实服务集成测试，按仓库约定使用隔离 schema 和唯一队列。

开发时 `pnpm dev` 不包含管理端，需另行运行 `pnpm --filter @nyz-rag/admin dev`；也可复用已运行的环境，避免重复启动服务。不要让宿主机与容器 worker 同时消费同一队列，不修改其他项目的 PostgreSQL/Redis 服务。

真机访问的现状与前置配置：

- 暴露范围：容器端口只绑定 127.0.0.1，手机无法直接访问；本机开发模式则不同，web、admin 的 `dev` 脚本为 `vite --host 0.0.0.0`，API 也监听 `0.0.0.0`，只要防火墙放行，同一局域网内的设备就能访问管理端和 API。真机测试只在可信网络进行，测试结束后恢复防火墙规则，不公开数据库或 Redis。
- API 地址：`.env.example` 中 `VITE_API_URL=http://localhost:3010`，手机上的 localhost 指向手机本身，必须改为本机局域网地址（如 `http://192.168.x.x:3010`）后重启 Vite。Vite 未配置 `/api` 代理。
- 允许来源：`WEB_ORIGINS`、`ADMIN_ORIGINS` 默认只包含 localhost 与 127.0.0.1，须加入局域网来源（如 `http://192.168.x.x:5010`、`:5011`）并重启 API，否则携带 Cookie 的请求会被拒绝。
- Cookie：非生产环境默认不带 `Secure`（`USER_COOKIE_SECURE`、`ADMIN_COOKIE_SECURE` 未设置时取决于 `NODE_ENV`），HTTP 局域网地址可以正常登录；同一 IP 不同端口属于同站，`SameSite=Strict` 不受影响。

复用已有测试服务时记录访问方式与上述配置改动，不在文档中写入秘密值，测试后还原 `.env`。

## 9. 验收标准

- [ ] 320 CSS px 及以上的目标视口中，所有页面无非预期横向滚动、控件重叠或关键内容裁切。
- [ ] 表格和代码块的横向滚动限制在局部容器，手机摘要中的省略信息有完整查看路径。
- [ ] 客户端在真机键盘打开时可编辑、发送、停止生成和操作筛选；安全区不遮挡主要按钮。
- [ ] 管理端所有现有路由完成手机检查，登录、导航、查询、详情和已有表单操作可完成。
- [ ] 长弹窗和详情抽屉在短屏、横屏下可访问全部字段、错误提示、关闭及提交操作。
- [ ] 抽屉和弹窗关闭后恢复焦点与背景滚动，跨断点无重复导航或遮罩残留。
- [ ] 主要触控区域达到计划尺寸，图标按钮具备名称，键盘操作和用户缩放未被禁用。
- [ ] 移动展示与桌面展示复用数据及业务状态，不新增重复请求，不改变权限、聊天或保存行为。
- [ ] 桌面关键页面及现有业务路径回归通过，工程验证命令无本次改动引入的失败。
- [ ] 已记录实际设备、浏览器版本、截图/操作结果、未覆盖范围和遗留问题；P0 问题清零。

## 10. 风险与发布策略

| 风险 | 应对措施 |
| --- | --- |
| 共享弹窗变更影响多处业务 | 先列调用方，验证账号、配置、权限和确认四类弹窗；必要时保留业务级布局覆盖 |
| 移动卡片与桌面表格功能分叉 | 复用请求、状态和操作函数；以逐页能力清单核对，禁止仅在桌面保留关键动作 |
| 软键盘行为因系统不同而变化 | 真机优先验证；只在复现后引入额外视口逻辑，并记录适用设备 |
| 导航断点与路由生命周期相互影响 | 覆盖抽屉打开时跳转、当前路由重选、退出和跨断点场景 |
| 适配范围膨胀为全面重构 | 保留现有设计和业务结构，以复现问题与验收条目为边界 |
| 缺少设备或真实权限账号 | 明确记录验证缺口，不能用桌面模拟或构建通过代替对应验收 |

按共享基础、客户端、管理端分阶段交付，发布前在同一候选版本上完成联合验收；不默认自动提交、推送或部署。发布后重点观察手机登录、聊天输入、表单提交和导航问题。若出现阻塞性回归，按项目发布机制回退本次前端构建或对应改动，不涉及数据库回滚。
