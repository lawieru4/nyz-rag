# 真实问题检索评估集方案

状态：方案，未实施。目标是建立以真实问题为主、人工标注、可重复运行的检索评估集，作为切片、检索、Rerank、问题改写等调整的回归基线。[切片改造](chunking-design.md)以本评估集的基线验收。

## 一、目标与原则

- **评估真实链路**：直接调用问答使用的 `retrieve()`（关键词 + 子块向量 + 摘要召回、RRF、Rerank），并能逐路消融；不再只评估关键词基线。
- **标注不随切片变化**：标注到「文章 + 相关度 + 证据原文」，不记录切片 ID。切片层面的命中由证据原文与召回切片的文本重叠计算，切片方案改变后标注仍然有效。
- **以真实问题为主**：真实用户提问和业务人员盲写的问题为主体，现有 50 条合成题单独标记，只用于冒烟测试，不与真实题合并计算指标。
- **减少标注偏差**：用多种检索配置的结果合并成候选池（pooling），不只标注当前系统召回的文章。
- **可复现、可对比**：数据集按版本冻结；每次运行记录语料与配置版本并保存结果，两次运行可逐题对比。
- **防止过拟合**：数据集划分 dev / test，调参只看 dev，test 只在阶段验收时运行。

## 二、前置条件

1. **全量语料入库**：业务库目前没有文档。需要在管理后台配置 nyzdata token 后完成全量同步（约 7068 篇），并在模型配置中选择 Embedding 模型完成向量化。评估语料以某一次同步结果为准，记录文档数、`PARSER_VERSION`、切片版本和 Embedding 模型。
2. **评估用知识库配置固定**：`topK`、`similarityThreshold`、`rerankEnabled`、`maxContextLength` 在运行记录中保存，比较两次运行时只改变待验证的变量。
3. **只取接口来源文章**：评估语料只包括文章接口来源的 ready 主文档（不含重复文档）。

## 三、数据集格式（schemaVersion 2）

```json
{
  "schemaVersion": 2,
  "name": "nyz-rag-real-v1",
  "version": "2026-11-15",
  "provenance": "真实用户提问（脱敏改写）与业务人员盲写问题，候选池人工标注，20% 双人复核",
  "corpus": { "documents": 7068, "parserVersion": 5, "chunkerVersion": 1 },
  "questions": [
    {
      "id": "r0001",
      "question": "无序岩盐正极里晶格畸变起什么作用？",
      "history": [],
      "filters": null,
      "type": "mechanism",
      "source": "expert",
      "split": "dev",
      "answerable": true,
      "notes": "",
      "labels": [
        { "articleKey": "10383698255", "relevance": 3, "evidence": ["局部晶格畸变可抑制阳离子短程有序，激活传统理论认为无效的1-TM扩散通道，从而拓展锂离子渗流网络"] },
        { "articleKey": "<另一篇候选文章>", "relevance": 0, "evidence": [] }
      ]
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `history` | 多轮追问的前几轮 `{ question, answer }`，单轮问题为空数组 |
| `filters` | 与 `/api/chat` 的 `filters` 相同；大多数问题为 `null` |
| `type` | 题型，见第四节 |
| `source` | `real`（真实用户）/ `expert`（业务人员盲写）/ `synthetic`（合成） |
| `split` | `dev` / `test` |
| `answerable` | 知识库中没有答案的问题为 `false`，`labels` 中不能有相关度 ≥ 2 的文章 |
| `labels[].relevance` | 0～3，见第五节；保留 0 分记录，表示「已判定不相关」，与「未判定」区分 |
| `labels[].evidence` | 相关度 ≥ 2 时必填，原文中能回答问题的句子，可有多段 |

校验规则：ID 唯一、问题非空、`articleKey` 存在于语料、证据原文能在文章正文中找到（规范化后子串匹配）、`answerable=false` 时没有相关度 ≥ 2 的标注、每道 `answerable=true` 的题至少有一篇相关度 ≥ 2 的文章。

现有 `packages/processing/test/evaluation/retrieval-dataset.json`（schemaVersion 1）保留为合成集，评估命令兼容读取，指标单独报告。

## 四、题目来源与构成

### 4.1 来源

| 来源 | 数量 | 做法 |
| --- | --- | --- |
| 真实用户提问 | 尽量多 | 从 `chat_messages` 导出（差评优先，按问题去重）；人工去除个人信息、补全指代后改写为独立问题，多轮追问保留 `history` |
| 业务人员盲写 | 30～50 条 | 请 2～3 名熟悉 nyzdata 内容的人员在**不看文章**的情况下写出实际会问的问题，按第 4.2 节题型给出数量要求 |
| 合成题 | 现有 50 条 | 不进入真实集，只用于冒烟测试 |

### 4.2 题型配比（第一版目标 ≥ 80 条，持续扩充到约 150 条）

| 类型 `type` | 占比 | 示例 |
| --- | --- | --- |
| `fact`：单篇事实 | 30% | 某材料的实测容量是多少 |
| `mechanism`：机制/原因 | 15% | 为什么晶格畸变能拓展锂离子通道 |
| `compare`：跨篇对比或汇总 | 15% | 近期钠离子电池正极有哪些路线 |
| `metadata`：机构/期刊/负责人/项目 | 15% | 某大学某团队发表在 JACS 的工作 |
| `term`：化学式、术语精确匹配 | 10% | Na₀.₉ 相关研究 |
| `followup`：多轮追问 | 10% | 「它的负责人是谁」（带历史） |
| `unanswerable`：知识库中没有答案 | 5% | 与能源化学无关或语料未覆盖的问题 |

真实用户问题按实际分布收录，不强行凑比例；比例不足的题型由盲写补齐。

### 4.3 划分

按题型分层随机划分，dev 70%、test 30%。划分后写入 `split` 字段，之后不再变更；新增题目进入下一版本时再分配。

## 五、标注规范

### 5.1 相关度

| 分值 | 含义 |
| --- | --- |
| 3 完全回答 | 文章中有直接、完整回答问题的内容 |
| 2 部分回答 | 文章中有答案的关键部分，但不完整，或需要结合其他文章 |
| 1 相关背景 | 主题相关，但不能回答问题 |
| 0 不相关 | 与问题无关 |

- 只依据文章正文判断，不依据标题猜测。
- 多篇文章内容相同（转载、改写）时各自标注，不因重复降分。
- 证据原文选取最能直接回答问题的一两句，不超过 200 字；答案分散在多处时可以有多段证据。

### 5.2 候选池

每道题用以下配置分别检索，每种取前 10 篇文章，合并去重后作为候选池（约 15～30 篇）：

1. 离线词项重叠基线（`rankOffline`）
2. 关键词检索（含元数据加权）
3. 子块向量检索
4. 摘要召回
5. 混合检索 + Rerank（配置了 Rerank 模型时）

标注人逐篇打分；认为池中遗漏了相关文章时，可以通过全文搜索手动补充 `articleKey`。候选池外未判定的文章在计算指标时按不相关处理，报告中同时给出「top-K 中未判定文章的比例」，比例过高说明需要补充标注。

### 5.3 质量控制

- 标注人 2 名（熟悉业务），裁决人 1 名。
- 抽取 20% 的题目双人独立标注，计算相关度的加权 Cohen's κ；κ < 0.6 时修订标注规范后重新标注这部分。
- 双人分歧（分差 ≥ 2，或一方 ≥ 2 而另一方 < 2）由裁决人确定。
- 每道题记录标注人与标注时间，状态依次为 `draft` → `labeled` → `reviewed`，只有 `reviewed` 的题目导出到冻结版本。

### 5.4 隐私

真实用户问题在进入评估集前必须脱敏（去除姓名、联系方式、单位内部信息等），并且不保留 `chat_messages` 的 ID 与提问人。冻结的 JSON 经脱敏复核后才提交到仓库；未复核的导出文件放在 `.nyz-data/evaluation/`（gitignored）。

## 六、指标

### 6.1 检索指标（按 split 和题型分别输出）

| 指标 | 定义 |
| --- | --- |
| Recall@5 / @10 | top-K 文章中命中的相关文章（相关度 ≥ 2）占全部相关文章的比例 |
| MRR | 第一篇相关文章名次的倒数 |
| nDCG@10 | 按相关度 0～3 分级计算，增益为线性（与现有实现一致） |
| Evidence Hit@5 | top-5 切片中，同一相关文章的切片文本（规范化：NFKC、去空白与标点）覆盖证据原文中文二元组的比例 ≥ 0.8 即为命中；按题目求平均。不依赖切片 ID |
| 上下文精度 | 实际进入回答上下文的切片中，来自相关文章（相关度 ≥ 2）的比例 |
| 未判定比例 | top-10 文章中没有标注的比例，用于判断标注是否需要补充 |
| 检索耗时 | p50 / p95 |

`unanswerable` 题不计入上述召回类指标，另行报告各路最高得分的分布，用于设定相似度阈值。

### 6.2 回答指标（第二阶段）

| 指标 | 定义 |
| --- | --- |
| 引用正确率 | 回答中引用的文章属于相关文章（相关度 ≥ 2）的比例 |
| 拒答正确率 | `unanswerable` 题中模型明确说明资料不足的比例；`answerable` 题中误拒答的比例 |
| 忠实度 | LLM 评审判断回答中的事实是否都能在上下文中找到依据，人工抽检 20% 校准 |

## 七、工具实现

| 步骤 | 内容 | 预估 |
| --- | --- | --- |
| A | 评估命令增加 `--mode=hybrid`：复用 API 的检索接线（`retrieve()` + 数据库召回 + 默认模型供应商），`--variant=keyword,vector,summary,fused,rerank` 逐路消融；输出文章级与 Evidence Hit 指标，按题型分组 | 1 天 |
| B | 每次运行保存到 `.nyz-data/eval-runs/<时间>-<名称>.json`：语料版本、知识库参数、模型、每题的召回列表与得分、汇总指标；新增 `pnpm evaluate:compare <运行A> <运行B>`，输出指标差值与每题名次升降 | 1 天 |
| C | 数据集 schemaVersion 2 的类型、校验与兼容读取（v1 视为 `source=synthetic`）；`--split=dev|test` | 0.5 天 |
| D | 迁移新增 `eval_questions`（问题、历史、过滤条件、类型、来源、split、answerable、状态、备注）与 `eval_judgments`（question_id、article_key、relevance、evidence[]、标注人、时间，按题目 + 文章 + 标注人唯一）；候选池生成命令 `pnpm evaluate:pool` 写入待标注文章 | 1 天 |
| E | 管理端「评估集」模块：问答记录详情中「加入评估集」（带出问题与历史，进入脱敏编辑）；题目列表与状态筛选；标注页左侧候选文章列表、右侧文章正文，0～3 打分、划选证据、手动补充文章；双人标注与裁决视图；导出冻结版本 JSON | 3～4 天 |
| F | 回答层评估：对评估集运行完整问答（不保存为问答记录），计算引用正确率、拒答正确率，接入 LLM 评审 | 2 天 |

E 完成前可以先用表格过渡：`evaluate:pool` 导出候选池表格，人工填写后由导入命令写回，以便尽早开始标注。

## 八、使用流程

```sh
# 1. 生成候选池（新增或修改题目后）
pnpm --filter @nyz-rag/processing evaluate:pool --dataset=nyz-rag-real-v1

# 2. 标注完成后导出冻结版本
#    管理端「评估集」→ 导出 → packages/processing/test/evaluation/real-v1.json

# 3. 记录基线
pnpm --filter @nyz-rag/processing evaluate:retrieval --mode=hybrid --dataset=<路径> --split=dev --name=baseline

# 4. 修改检索或切片后再运行，并与基线对比
pnpm --filter @nyz-rag/processing evaluate:retrieval --mode=hybrid --dataset=<路径> --split=dev --name=parent-child
pnpm --filter @nyz-rag/processing evaluate:compare baseline parent-child
```

命令名与参数在实现时确定，以上为约定的形式。

## 九、验收规则

检索或切片的改动合入前，在 dev 集上满足：

- nDCG@10、Recall@10 不下降（容差 1 个百分点），Evidence Hit@5 不下降；
- 任一题型的 nDCG@10 下降不超过 3 个百分点，超过时在说明中逐题解释；
- 检索耗时 p95 增加不超过 30%，超过时说明原因。

每完成一个阶段（例如切片改造上线前），在 test 集上运行一次并记录到 `docs/module-status.md`。
